## 🧭 FastAPI 大师课：第28-29节：路径参数

我们先从路径参数开始回顾。路径参数是URL中动态命名的片段，很多时候我们需要获取某一个资源或某一个实体，而这个资源往往由某种唯一值来标识，例如一个ID。问题在于，我们不可能为每一个可能出现的ID都在应用里单独定义一条路由，所以需要让路由路径中的某一部分变成动态的、灵活的，能够对任意值作出反应，这就是路径参数的作用。

![](img/6db122bac72f7ea7d3a04743d101c212_1.png)

在路由定义中，例如传给`get`方法的字符串里，我们可以把某一段用花括号包起来，告诉FastAPI去匹配这个位置上的任意片段或任意值。比如下面这条路由，把`coffee_id`用花括号包住，FastAPI就会匹配`/coffees`后面的任意值。路由处理函数运行时，FastAPI会把该路径值作为参数传给处理函数。

```python
@app.get("/coffees/{coffee_id}")
def read_coffee(coffee_id: int):
    ...
```

这里有一个关键点：函数参数名必须和路径参数名完全一致，FastAPI才能把两者关联起来。另外，我们还可以声明函数参数的类型，例如写成`coffee_id: int`。虽然路径参数到达时是字符串，但只要FastAPI有能力转换，它就会自动转换成声明的数据类型。也就是说，如果处理函数函数体执行了，就说明转换成功；如果FastAPI无法把动态路径段转换成函数要求的参数类型，它就会返回错误响应。

下面把路径参数的关键点整理出来，方便你快速复习。

- 路径参数是URL中动态命名的片段，用来匹配任意资源标识值。
- 在路由字符串中用花括号包裹动态段，例如`/coffees/{coffee_id}`。
- 路由处理函数的参数名要与路径参数名完全一致。
- 可以给函数参数加类型注解，FastAPI会在可能时自动转换。
- 转换失败时，FastAPI会返回错误响应，而不是继续执行函数体。

理解路径参数之后，接下来要处理一个常见情况：客户端请求的资源在服务器上找不到时，应该返回什么状态码。


## 🚫 FastAPI 大师课：第28-29节：404状态码与HTTPException

上一节我们介绍了路径参数如何匹配动态资源，本节我们来看看资源找不到时应该怎么响应。404状态码表示“未找到”，这是服务器在告诉客户端：你请求的某个资源标识符，我在服务器上无法定位。404属于客户端错误，不属于服务器错误，所以它归在400系列错误里。

在Python函数中，如果没有显式返回值，函数会隐式返回`None`，这是Python表示“空”或“不存在”的对象。JSON会把`None`转换成对应的`null`。问题在于，简单返回空并不一定代表发生了某种错误。以房间示例来说，当找不到房间时，函数只是返回`None`，状态码仍然是200，虽然从技术上讲这是不正确的，因为我们没有找到请求的资源。

因此，找不到请求的实体时应该返回404。做法是从FastAPI导入一个特殊错误类`HTTPException`，在路由处理函数体里使用`raise`关键字，后面跟这个类的实例。构造实例时传入两个参数：第一个是`status_code`，表示期望的状态码，可以写整数`404`，更好的做法是引用`status`模块里的常量，这样能减少输入错误，也能提供更多上下文，因为这些常量包含对应状态码的名称；第二个是`detail`，用于提供自定义错误消息，FastAPI会把它作为实际响应返回给客户端。

```python
from fastapi import HTTPException, status

raise HTTPException(
    status_code=status.HTTP_404_NOT_FOUND,
    detail="Requested resource was not found"
)
```

这样请求在技术上仍然会完成，因为服务器会返回一些内容，但返回的是404状态码，并且响应负载和原本请求的资源不同。下面列出使用`HTTPException`时需要注意的要点。

- 找不到请求实体时返回404。
- 导入`HTTPException`并使用`raise`抛出实例。
- `status_code`可以写`404`，也可以使用`status`模块常量。
- `detail`用于提供返回给客户端的自定义错误消息。
- 服务器仍会返回响应，但状态码和负载会体现错误。

处理完错误状态之后，路由匹配本身也可能出现顺序问题，接下来我们看看路由顺序为什么重要。


## 🧱 FastAPI 大师课：第28-29节：路由顺序

上一节我们介绍了如何返回404错误，本节我们来看看路由顺序。FastAPI收到请求后，会把请求匹配到合适的路由，并且会按照路由在文件中声明的顺序从上到下解析。问题在于，带路径参数的路由可能会意外匹配到另一条带硬编码片段的路由。

例如，我们有一个端点`/coffee/milk`，如果把它放在`/coffee/{coffee_id}`这条路由的后面，就会出现问题。带`coffee_id`路径参数的路由会匹配到`milk`，它会认为URL中的动态段就是字符串`milk`。因此，当你有一个类似`/coffee/milk`的硬编码URL时，应当把它放在带动态部分或路径参数的路由上面。这样服务器会先查找`/coffee/milk`，如果没有匹配，再继续匹配`/coffee/{coffee_id}`这样的动态路由。

```python
@app.get("/coffee/milk")
def get_milk_coffee():
    ...

@app.get("/coffee/{coffee_id}")
def get_coffee(coffee_id: int):
    ...
```

下面把路由顺序的规则列出来，方便记忆。

- FastAPI按路由声明顺序从上到下解析。
- 固定段路由应放在动态段路由之前。
- 带路径参数的路由可能误匹配硬编码片段。
- `/coffee/milk`应放在`/coffee/{coffee_id}`上面。
- 先匹配固定路由，再匹配动态路由，可以避免误匹配。

路由顺序理清之后，接下来我们看看如何让用户下载项目中的固定文件，也就是静态文件。


## 📁 FastAPI 大师课：第28-29节：静态文件

上一节我们介绍了路由顺序，本节我们来看看静态文件。静态文件基本上就是固定资产或固定文件，可以允许用户下载。你可以在项目里创建一个示例目录，目录叫什么都可以，有时叫`static`，有时叫`assets`。FastAPI能够为指定目录下嵌套的每个文件创建路由，而且可以继续深入任意多层目录。

例如，如果有一个嵌套目录叫`some_directory`，就可以通过类似`/assets/some_directory/文件名`的路径访问。要配置静态文件，我们在代表FastAPI服务器的`app`上调用`mount`方法，然后提供前缀，也就是用户访问的路径段。这个前缀通常与文件夹同名，但不必完全相同，可以灵活变化。`app.mount`的第二个参数是导入的`StaticFiles`实例，同时还要提供`name`参数。配置完成后，整个文件夹都会暴露，每个嵌套文件都会获得对应的下载路径。

```python
from fastapi.staticfiles import StaticFiles

app.mount("/static", StaticFiles(directory="static"), name="static")
```

这里要特别注意安全：静态文件只应该是公开文件，也就是你不怕给用户看的文件。不要在这个目录里存放任何敏感信息或敏感文件。即使你没有提供任何方式让用户知道文件名或嵌套结构，这些文件在技术上仍然是公开可用的，这会带来安全风险。因此使用静态文件功能时，只应允许用户下载你愿意公开的文件。下面列出静态文件配置与安全方面的要点。

- 静态文件是固定资产或固定文件，允许用户下载。
- 通常创建`static`或`assets`目录，名称不固定。
- 使用`app.mount`挂载目录，并指定访问前缀。
- 第二个参数是`StaticFiles`实例，同时提供`name`参数。
- 目录可以任意层级嵌套，每个文件都有对应路径。
- 只放公开文件，绝不放敏感信息或敏感文件。

静态文件让下载变得简单，但开发过程中还需要调试代码，接下来我们看看如何在VS Code里调试FastAPI。


## 🐞 FastAPI 大师课：第28-29节：VS Code调试

上一节我们介绍了静态文件，本节我们来看看VS Code调试。VS Code左侧菜单有一个很方便的按钮，上面有虫子图标和播放图标。我们可以配置一些设置来创建`launch.json`文件，本质上是创建一个预配置的FastAPI服务器实例，让它运行在Uvicorn上。运行服务器后，在代码文件里放置断点：把鼠标移到行号左侧的装订线位置，点击即可。断点放在哪里，服务器运行到那一行代码时就会暂停。

当然，仍然需要打开浏览器或终端，作为客户端向对应路由发起请求。请求到达后，如果遇到断点，FastAPI就会暂停，这时可以回到VS Code进行调试，逐行执行代码。左侧面板会显示所有已声明的变量以及所有函数参数。你也可以把断点放在`for`循环里，实际观察每一次迭代。顶部工具栏会提供一组按钮来帮助你完成这些操作。

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "FastAPI",
      "type": "python",
      "request": "launch",
      "module": "uvicorn",
      "args": ["main:app", "--reload"]
    }
  ]
}
```

下面把常用调试操作列出来，方便你上手。

- `Continue`按钮会跳到下一个断点。
- 可以放置任意多个断点。
- `Step Over`会跳到下一条逻辑执行行。
- `Step Into`会进入更深一层，例如进入函数调用内部。
- 在函数调用起点使用`Step Into`，可以逐行查看函数内部代码。
- 熟悉这些命令后，可以快速在代码库中导航到目标行。

此外，我们还简单提到了FastAPI的VS Code扩展，它可以让你快速跳转到应用中声明的任意路由。这个扩展未来应该还会继续扩展，引入更多功能。下面把调试与扩展部分的要点汇总一下。

- 使用左侧调试按钮和`launch.json`配置FastAPI服务器。
- 断点会让服务器在对应代码行暂停。
- 仍需通过浏览器或终端发起请求触发路由。
- 左侧面板可查看变量和函数参数。
- 调试工具栏支持继续、单步跳过、单步进入等操作。
- FastAPI VS Code扩展可以快速跳转到已声明路由。
