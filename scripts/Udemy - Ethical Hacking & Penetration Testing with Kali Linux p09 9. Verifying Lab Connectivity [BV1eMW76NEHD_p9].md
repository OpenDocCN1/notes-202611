
# 道德黑客与 Kali Linux 渗透测试：9：验证实验室连通性 🌐


在本节课中我们将要学习如何确认刚才配置的虚拟机网络是否真的通了。我们会分别在 Kali 和 Metasploitable 里查看 IP 地址，然后用 ping 命令让两台机器互相发送测试包。如果 ping 不通，我也会告诉你最常见的原因和修复方法。请不要跳过这一节，哪怕它很短。这一步验证能帮你立刻发现几乎所有安装问题，而不让它变成三节课后你在做扫描或利用漏洞时才遇到的令人困惑的谜团。


## 在 Kali 中查看 IP 地址

上一节我们完成了虚拟机的网络配置，本节中我们来看看配置是否真的生效。

首先我们在 Kali 的终端窗口里操作。打开终端，输入命令 `ip a` 并按下回车键。屏幕上会列出几个不同的网络接口。其中有一个通常叫做 `lo`，它代表回环接口，意思是机器在跟自己说话，针对我们的实验可以直接忽略。我们真正需要关注的是其他接口，尤其是地址以 `192.168.56.x` 开头的那一个，这就是上一节 VirtualBox 分配给 Kali 虚拟机的 IP 地址。如果你看到的地址以这些数字开头，那就是我们想要的结果。这就是 Kali 虚拟机的 IP 地址。


## 在 Metasploitable 中查看 IP 地址

确认 Kali 的 IP 地址没有问题之后，本节中我们来看看目标机器这边是什么情况。

接下来我们在 Metasploitable 里做同样的检查。打开它的终端，再次输入 `ip a` 并回车。这次我们要找的也是 `192.168.56.x` 这个网段里的地址，通常会出现在 `ethernet0` 接口下。如果两台机器都能看到属于同一个网段的地址，就说明上一节设置的 host-only 网络在两端都已经正常工作。


## 用 Ping 测试两机互通

有了 IP 地址之后，本节中我们来看看两台机器能不能真的互相通信。

现在进行真正的连通性测试。回到 Kali 的终端，输入 `ping 192.168.56.101` 并回车。如果屏幕开始陆续显示回复，每条回复都带有往返时间，单位是毫秒，那就毫无疑问地证明了这两台机器能够通过我们私有、隔离的网络真正互相到达。测试完成后，按下 `Ctrl+C` 停止 ping 命令。


## 如果 Ping 不通怎么办

万一测试没有成功，本节中我们来看看怎么排查问题。

以下是常见故障及其排查步骤：
- 如果没有收到任何回复，而是出现 destination host unreachable，或者命令直接卡住什么都不返回，首先不要慌，也不要跳过这一节指望以后会自己好，因为它不会好。
- 根据经验，大约有 90% 的情况是上一节配置的网络适配器设置不匹配。
- 分别打开两台虚拟机的设置，仔细确认两者都选择了 host-only adapter，并且选用的是完全相同的那个适配器，而不是下拉菜单里两个看起来相似但实际不同的 host-only 适配器。
- 这种设置不匹配是这一步最常见的错误，一旦发现，修复起来非常简单。
