```text
原始数据 -> 清洗与塑形 -> 计算 -> 洞察 -> 决策
```

- 连接数据。
- 以及更多数据操作。

## ⚡ 数据分析与 Polars、Python：01.2：Rust 引擎与性能优势


Polars 的一个显著特点是，它的源代码使用一种更低层的语言 Rust 编写。Rust 是为速度、效率和内存安全而设计的语言。Rust 比 Python 难得多，但 Polars 的美好之处在于，我们不需要编写任何 Rust 代码。我们仍然编写 Python 代码来使用 Polars 库。Python 代码只是与底层 Rust 代码进行接口或通信，从而非常高效地执行数据操作。


上一段说明了 Polars 的底层语言，本节我们总结这种设计带来的好处。我们既能获得 Python 更简单的语法，这种语法常被认为对初学者更友好，又能获得 Rust 的速度，而 Rust 是世界上速度最快的语言之一。因此，这确实是一种兼顾多方面的组合。可以用下面的流程理解这种接口关系：


```text
Python 代码 -> Polars API -> Rust 引擎 -> 高效数据操作
```


讲完底层设计后，下面回顾 Polars 的历史。Polars 最初是开发者 Richie Vik 的一个副项目，他好奇 Rust 如何应用到数据科学领域。Polars 于 2021 年 3 月首次发布，现在由一个活跃的全球开源贡献者团队维护。截至 2026 年，它在 GitHub 上拥有超过 35000 个星标。


如果你以前用过 pandas，那很好；如果没有用过，也完全没有关系。Polars 常被称为 pandas 的继任者。pandas 在下载量上仍然是市场领先者，但 Polars 在 Python 数据科学生态系统中的人气正在快速上升。pandas 最初得名于面板数据结构（panel data structures），这简单来说意味着三维数据集，而它与熊猫这种动物的联想完全是巧合。


Polars 这个名字很巧妙，原因有两个。以下是这两个原因：


- 北极熊比熊猫更强壮，这像是对 pandas 的温和玩笑式调侃，Polars 想强调自己比 pandas 更快、更强、更高效。
- Rust 文件以 `.rs` 扩展名结尾，就像 Python 文件以 `.py` 结尾一样，因此 Polars 这个库名也方便地以 Rs 结尾，提醒人们它是用 Rust 开发的。


因此，从这两个原因看，Polars 是一个相当聪明的名字。那么 Polars 与 pandas 到底有什么不同？正如前面提到的，Polars 是从零开始使用 Rust 语言构建的，平均而言比 Python 更快、更高效。这意味着它运行得更快，同时占用更少的系统资源。


## 🧵 数据分析与 Polars、Python：01.3：并行化与列式存储


Rust 也从底层开始支持并行化，这意味着代码可以跨多个线程和多个 CPU 核心运行。本质上，Polars 可以把工作拆分到计算机可用的资源上，让工作并行发生，然后再把结果合并起来。例如，如果你要求对两个不同的列执行两个独立操作，Polars 可以把这项工作拆分，然后把结果合并成一张最终结果表。


可以用一个类比来理解：这就像同一家公司里的多名员工一起做一项任务，每个人都分担一部分工作，从而加快最终结果的产出速度。讲完并行化后，本节我们来看看 Polars 使用的数据存储格式。Polars 使用列式 Apache Arrow 数据存储格式，columnar 简单来说就是基于列的意思。


作为数据分析库的开发者，在如何存储一张表的数据上有两种选择。数据在内存中彼此越靠近，CPU 访问数据并执行操作的速度就越快，因为收集一次操作所需的值时，需要移动的距离更短。你可以优先把所有行的值存储在一起，也可以优先把所有列的值存储在一起，这个选择会影响哪些类型的操作更快。以下是两种存储选择的基本区别：


- 行式存储：优先把同一行的所有值放在一起。
- 列式存储：优先把同一列的所有值放在一起。


Polars 优先采用列式存储，因此列式操作通常比行式操作更快。Polars 团队愿意下注认为列式操作更常见，讲师也同意这一点，因为一般执行数据分析时确实如此。理解完存储方式后，本节继续看 Polars 另一个有意思的特性：惰性求值。


## ⏳ 数据分析与 Polars、Python：01.4：惰性求值


Polars 有一个有趣特性叫惰性求值（lazy evaluation）。它会延迟查询计算，直到我们要求 Polars 运行它。因此，我们可以逐步构建复杂的顺序数据变换。因为 Polars 知道到达最终结果所需的所有步骤，所以它可以优化最终执行的查询，减少低效操作，并尽量减少需要执行的总步骤数。这个特性叫 lazy frames，我们会在课程后面介绍。


可以用下面的流程理解惰性求值的基本思想：


```text
查询计划 -> 优化 -> 执行
```
