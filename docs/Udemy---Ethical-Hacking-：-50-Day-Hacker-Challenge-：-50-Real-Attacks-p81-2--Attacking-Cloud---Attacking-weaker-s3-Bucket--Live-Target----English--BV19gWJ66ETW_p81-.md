
# Ethical Hacking 50-Day Challenge：02：攻击配置错误的S3存储桶 🛡️


在本节课中，我们将学习如何通过真实案例攻击配置错误的云存储，特别是AWS S3存储桶。本课适合初学者，会用大白话把每一步讲清楚，让你明白黑客是如何利用云端存储漏洞获取数据的。即使你之前没有接触过云安全，也能跟着思路理解整个过程。


## 一、课程背景与目标概述 📋


上一节我们介绍了通用漏洞利用和云端利用的基础知识。本节中我们来看看如何攻击弱配置的S3存储桶，重点是理解云存储权限设置不当会带来什么后果。


![](img/b64a158be8aad0061bf1b971c999b1bc_1.png)

![](img/b64a158be8aad0061bf1b971c999b1bc_3.png)

这节课的核心目标非常明确，就是找到一个真实存在的、配置不当的S3存储桶，并通过它访问本不应该公开的数据。我们会用一个真实网站作为演示目标，走完从访问页面到下载文件的完整过程。你可以把S3存储桶想象成云端的一个文件夹，只不过这个文件夹的门锁没有锁好。


## 二、目标环境与初步访问 🎯


首先，我们需要确定今天要攻击的目标。这个目标就是一个S3存储桶，它的名称和相关信息会在课程中给出。你只需要按照指引访问目标网站，就能开始后续操作。


以下是访问目标的具体步骤：


1. 打开浏览器，输入目标网址进入相关页面。
2. 按照页面提示继续操作，直到进入第三阶段。
3. 第三阶段会直接跳转到一个文件上传页面。
4. 在上传页面中，使用抓包工具拦截发出的请求。


![](img/b64a158be8aad0061bf1b971c999b1bc_5.png)

抓包这个动作很简单，就是让你的工具先拦住浏览器发给服务器的数据包，这样你就可以查看请求里的内容。拦截之后，转发请求，查看服务器返回的响应。这时候你会看到页面里提供了一些测试数据，也就是我们需要关注的目标文件。


![](img/b64a158be8aad0061bf1b971c999b1bc_7.png)

## 三、使用AWS命令行工具列出存储桶文件 🖥️


![](img/b64a158be8aad0061bf1b971c999b1bc_9.png)

![](img/b64a158be8aad0061bf1b971c999b1bc_11.png)

除了通过浏览器操作，我们还可以使用命令行工具直接和AWS S3交互。这是更专业、更直接的方法，不需要依赖网页界面。


核心命令如下：


```bash
aws s3 ls s3://你的桶名
```


![](img/b64a158be8aad0061bf1b971c999b1bc_13.png)

![](img/b64a158be8aad0061bf1b971c999b1bc_14.png)

这条命令的意思是列出指定S3存储桶里的所有文件。在演示中，讲师已经安装好了Windows版本的AWS命令行工具，只需要把刚才复制的存储桶名称填进去，运行命令就能看到桶里的文件列表。


![](img/b64a158be8aad0061bf1b971c999b1bc_16.png)

![](img/b64a158be8aad0061bf1b971c999b1bc_18.png)

以下是操作时需要注意的要点：


- 确保AWS工具已经正确安装并配置。
- 存储桶名称必须准确无误，否则无法列出文件。
- 使用aws s3 ls命令时，后面要跟上完整的S3路径。


运行成功后，你会看到一个文件列表，这些文件就是不同用户不同时间上传的内容。


![](img/b64a158be8aad0061bf1b971c999b1bc_20.png)

## 四、访问特定路径并下载文件 📂


在文件列表中，我们特别关注/order这个路径。之所以选择这个路径，是因为之前的请求记录里，服务器专门处理过这个地址，说明这里可能存放着我们想要的数据。


![](img/b64a158be8aad0061bf1b971c999b1bc_22.png)

以下是我们可以看到的文件类型：


![](img/b64a158be8aad0061bf1b971c999b1bc_24.png)

- 不同时间段上传的文件
- 其他用户提交的成功记录
- 图片和其他类型的云存储数据


![](img/b64a158be8aad0061bf1b971c999b1bc_26.png)

因为这个存储桶存在配置错误，它允许所有人访问里面的所有数据。这意味着，任何人都可以下载其他合法用户上传的文件，而不需要任何权限验证。


![](img/b64a158be8aad0061bf1b971c999b1bc_28.png)

![](img/b64a158be8aad0061bf1b971c999b1bc_30.png)

你可以尝试下载其中的某个文件，比如编号为215的提交文件。下载成功后，你会发现这是一个真实用户上传的内容，这就证明了漏洞的存在。同样地，你可以继续下载桶里的所有文件，因为这里没有访问控制。


![](img/b64a158be8aad0061bf1b971c999b1bc_32.png)

## 五、漏洞原理总结与防护建议 🔐


![](img/b64a158be8aad0061bf1b971c999b1bc_34.png)

![](img/b64a158be8aad0061bf1b971c999b1bc_36.png)

整个攻击过程的根本原因是S3存储桶的访问权限设置错误。核心逻辑可以表示为：


![](img/b64a158be8aad0061bf1b971c999b1bc_38.png)

![](img/b64a158be8aad0061bf1b971c999b1bc_40.png)

```
存储桶误配 = 公开读取权限 + 缺乏访问控制 = 任意用户可下载所有文件
```


简单来说，就是云存储的门没锁，导致任何知道桶名的人都能进去下载文件。为了避免这种情况，管理员应该限制存储桶的公开访问权限，并开启身份验证机制。


![](img/b64a158be8aad0061bf1b971c999b1bc_42.png)
