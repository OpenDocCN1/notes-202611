
# Ethical Hacking：04：LLMNR Poisoning实验 🎯

![](img/0ddf841b262b75394274b436a6929e8e_0.png)

在本节课中我们将要学习LLMNR中毒攻击的完整过程。这节课属于Active Directory渗透测试部分，重点在于如何在域环境中通过毒化LLMNR请求来获取目标用户的凭据哈希，并进一步尝试破解明文密码。

![](img/0ddf841b262b75394274b436a6929e8e_2.png)

LLMNR是本地链路多播名称解析协议，当DNS解析失败时，Windows系统会使用它来在本地网络中查找主机名。攻击者可以伪造响应，诱导受害机器发送Net-NTLMv2哈希。

![](img/0ddf841b262b75394274b436a6929e8e_4.png)

---
### 1. 环境准备与拓扑说明 🖥️

上一节我们介绍了Active Directory的基本概念，本节中我们来看看如何搭建LLMNR中毒的实验环境。

以下是实验环境中的关键角色和IP地址：

```text
受害机器：Windows 11
域控制器：Windows Server 2022（域名 MRV.dot.local）
攻击机器：Kali Linux（IP 192.168.5.129）
目标网段：192.168.5.0/24，网关 192.168.5.50
```

所有机器都需要处于同一个内网网段，确保攻击机能够监听到受害机器发出的广播请求。受害机器的DNS设置应指向域控制器，这样在域名解析失败时就会触发LLMNR广播。

![](img/0ddf841b262b75394274b436a6929e8e_6.png)

---
### 2. LLMNR中毒攻击原理 🔍

![](img/0ddf841b262b75394274b436a6929e8e_8.png)

本节我们已经了解了环境搭建方法，接下来我们讨论攻击的核心原理。

![](img/0ddf841b262b75394274b436a6929e8e_10.png)

![](img/0ddf841b262b75394274b436a6929e8e_12.png)

当用户在资源管理器或搜索面板中输入一个不存在的主机名或文件路径时，系统会先尝试DNS解析。如果DNS服务器返回不存在，Windows会通过LLMNR协议在本地子网内广播查询：

![](img/0ddf841b262b75394274b436a6929e8e_14.png)

```text
本机：有没有人知道 \\不存在主机名 的地址？
```

![](img/0ddf841b262b75394274b436a6929e8e_16.png)

攻击者监听这个广播并伪造响应，告诉受害机器“就是我，请访问我”。受害机器会尝试连接攻击机并主动发送Net-NTLMv2挑战响应哈希。

![](img/0ddf841b262b75394274b436a6929e8e_18.png)

这个过程可以用一个简单的公式表示：

![](img/0ddf841b262b75394274b436a6929e8e_20.png)

```
受害主机请求 → LLMNR广播 → 攻击机伪造响应 → 受害主机发送Net-NTLMv2哈希
```

![](img/0ddf841b262b75394274b436a6929e8e_22.png)

捕获到哈希后，攻击者可以离线字典攻击或暴力破解，从而还原用户的明文密码。

![](img/0ddf841b262b75394274b436a6929e8e_24.png)

---
### 3. 使用Responder发起中毒攻击 🛠️

前面一节我们讲解了中毒攻击的理论原理，本节中我们来看看如何用Responder工具实施攻击。

![](img/0ddf841b262b75394274b436a6929e8e_26.png)

![](img/0ddf841b262b75394274b436a6929e8e_27.png)

以下是启动Responder的常见命令和参数说明：

![](img/0ddf841b262b75394274b436a6929e8e_28.png)

```bash
responder -I eth0 -wrf
```

![](img/0ddf841b262b75394274b436a6929e8e_30.png)

参数解释如下：
- `-I eth0`：指定监听的网络接口，通常攻击机使用eth0。
- `-w`：启动WPAD代理服务器。
- `-r`：启用LLMNR和NBT-NS响应。
- `-f`：指定需要针对的特定请求。

执行命令后，Responder会开始监听本地网段中的LLMNR、NBT-NS和MDNS请求。当受害机器尝试访问不存在的资源时，Responder会立即回复并诱导其发送凭据哈希。

![](img/0ddf841b262b75394274b436a6929e8e_32.png)

在攻击机终端中，你会看到类似下面的输出：

```
[+] Captured NTLMv2 hash for user: admin
[+] Hash saved to: /usr/share/responder/logs/...
```

这意味着攻击成功，目标用户的Net-NTLMv2哈希已经被捕获到本地文件中。

---
### 4. 哈希提取与破解 🔓

![](img/0ddf841b262b75394274b436a6929e8e_34.png)

在上一节中我们使用Responder捕获到了目标的哈希值，本节中我们来看看如何将哈希保存并尝试破解。

![](img/0ddf841b262b75394274b436a6929e8e_36.png)

捕获到的哈希通常存储在Responder的日志文件中，格式类似于：

![](img/0ddf841b262b75394274b436a6929e8e_38.png)

```
admin::域名:1122334455667788:挑战值:响应值
```

![](img/0ddf841b262b75394274b436a6929e8e_40.png)

以下是常见的破解步骤：

![](img/0ddf841b262b75394274b436a6929e8e_42.png)

1. 将捕获的哈希内容复制到本地文本文件，例如 hash.txt。
2. 使用Hashcat等工具进行离线破解。

示例Hashcat命令：

![](img/0ddf841b262b75394274b436a6929e8e_44.png)

```bash
hashcat -m 5600 hash.txt 字典.txt
```

![](img/0ddf841b262b75394274b436a6929e8e_46.png)

这里 `-m 5600` 表示针对Net-NTLMv2哈希进行攻击。如果字典中包含目标用户的弱密码，工具将在短时间内还原明文密码。

破解成功后，终端会直接显示类似 `password:123456` 的结果，攻击者即可使用该明文密码登录目标系统。

### 5. 防御与缓解措施 🛡️

前一节我们完成了哈希捕获与破解的全过程，本节中我们来看看如何防御LLMNR中毒攻击。

![](img/0ddf841b262b75394274b436a6929e8e_48.png)

以下是常见的缓解措施：

- 在组策略中禁用LLMNR协议，防止系统在DNS失败后发送广播请求。
- 禁用NBT-NS（NetBIOS over TCP/IP）名称解析。
- 实施网络访问控制，限制未受信设备接入内网。
- 要求用户使用强密码，并定期更换，增加彩虹表和暴力破解的难度。
- 启用SMB签名，防止中间人攻击篡改响应。

![](img/0ddf841b262b75394274b436a6929e8e_50.png)

通过同时采用上述措施，可以显著降低LLMNR中毒攻击的成功率。

![](img/0ddf841b262b75394274b436a6929e8e_52.png)

### 6. 课程总结 📝

本节课中我们一起学习了LLMNR中毒攻击的原理、实验环境搭建、使用Responder捕获Net-NTLMv2哈希、利用Hashcat破解密码，以及相应的防御方法。

![](img/0ddf841b262b75394274b436a6929e8e_54.png)

LLMNR中毒是一种在Active Directory环境中非常常见且有效的凭据获取手段，防御的关键在于禁用不必要的名称解析协议并加强密码策略。希望你通过本节课掌握了这项技术，我们下节课再见。
