

CompTIA Linux+ V8：第5部分：使用.gitignore 🚫

在本节课中，我们将学习如何使用.gitignore文件，防止一些不该上传的文件被同步到Git仓库。很多初学者在使用Git的时候，容易不小心把包含密码的文件提交上去，这会带来安全隐患。通过本节课的学习，你将明白.gitignore到底是什么，如何在当前项目中创建它，如何配置全局忽略规则，以及如何通过实际操作验证敏感文件是否真的被忽略了。我们会用大白话把每一步都讲清楚，确保你看完之后可以直接动手操作。



什么是.gitignore 📂

在学习具体操作之前，我们先来聊聊.gitignore到底解决什么问题。

Git是一个版本控制工具，它会把你项目目录里的文件记录下来，并且同步到远程仓库。不过并不是所有文件都适合被同步。比如说，有些文件里面存了数据库密码、API密钥或者其他敏感信息，如果这些文件被上传到公共仓库，别人就可能看到你的密码，造成安全风险。为了避免这种情况，Git提供了一个名为.gitignore的文件，你可以在这个文件里列出不想被同步的文件名，Git就会自动跳过这些文件，不再把它们加入版本控制。

核心概念代码：
```
忽略文件名: .gitignore
```



在当前项目中创建.gitignore

上一节我们介绍了.gitignore的作用，本节中我们来看看如何在当前的Git项目目录里创建它。

创建.gitignore其实非常简单，它就是一个普通的文本文件，只不过名字前面带了一个点，叫做点gitignore。你只需要在项目目录下新建这个文件，然后把不想上传的文件名一行一行写进去就行。Git读取这个文件后，就会按照里面的名单来决定哪些文件不需要跟踪。

以下是创建本地.gitignore的步骤：

- 在你的Git项目目录下新建一个文本文件。
- 将文件重命名为.gitignore。
- 用文本编辑器打开它，写入需要忽略的文件名，每行一个。
- 保存文件，Git会自动生效。



配置全局.gitignore文件 🌍

除了给单个项目配置忽略规则，Git还支持全局设置，本节我们来看看怎么为所有仓库生效。

有时候你会发现，不管是哪个项目，某些文件永远都不想被提交，比如操作系统生成的临时文件或者编辑器产生的备份文件。这时候给每个项目都写一遍.gitignore就太麻烦了。Git允许你设置一个全局忽略文件，只要配置一次，所有的Git仓库都会遵守这份规则。

核心概念代码：
```bash
git config --global core.excludesfile ~/.gitignore_global
```

以下是全局.gitignore的使用要点：

- 在你的家目录下创建一个名为.gitignore_global的文件。
- 里面只需要列出文件名，不需要写绝对路径。
- 相对路径也是可以接受的。
- 配置完成后，任何Git仓库中出现的这些文件都会被忽略。



实战演示，保护密码文件不被上传 🔐

光讲理论不够，本节我们动手演示一下，看看.gitignore到底怎么生效。

假设我们现在有一个文件叫password.txt，里面写的是敏感值，比如数据库的登录密码。我们显然不希望这个文件被Git同步到远程仓库。下面我们就用echo命令和输出重定向来快速创建文件，并把它加入忽略列表，验证效果。

代码块：
```bash
echo passwords > passwords.txt
echo password.txt > .gitignore
git add *
git status
git commit -m "ignore file edit"
```

执行完这些命令后，你会看到以下结果：

- git status会提示有若干路径被忽略，其中就包括password.txt，这正是我们想要的效果。
- .gitignore本身会显示为未跟踪文件，因为它还没有被加入版本控制。
- 使用git commit -m "ignore file edit"提交时，你会发现.gitignore不会被忽略，它会正常被提交。
- 提交输出顶部会显示你的分支比origin/main领先一个提交，这意味着你需要执行git push来把变更同步到远程仓库。
- 推送完成后，你可以确认一切正常，且.gitignore已经被包含在提交中，而password.txt不会出现在远程仓库里。
