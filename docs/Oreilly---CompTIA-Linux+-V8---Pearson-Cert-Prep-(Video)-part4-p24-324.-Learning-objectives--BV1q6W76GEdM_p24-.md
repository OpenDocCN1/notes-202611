
# 🖥️ CompTIA Linux+ V8：09：Linux引导流程学习目标


在本节课中，我们将要学习Linux引导流程相关的核心知识点。这一节的内容主要围绕操作系统如何从按下电源按钮开始，一步步加载内核并进入运行状态展开。无论你是刚接触Linux的新手，还是已经有一些基础的学习者，理解引导过程都是排查系统无法启动问题的基础。我们会把整个启动流程拆解成几个清晰的步骤，帮助你建立完整的认知体系。


首先，我们会介绍Linux引导过程中涉及的所有组成部分。引导过程不是单一的动作，而是由硬件自检、固件加载、引导加载程序执行、内核初始化以及用户空间启动等多个环节共同完成的。每个环节都有自己的职责，任何一个环节出问题都可能导致系统无法正常开机。以下是Linux引导流程中涉及的主要元素列表：

![](img/2a2499007ef3d281a8f0f0a4f7ca7905_0.png)

- 固件层（BIOS或UEFI）：负责硬件自检和初始化
- 引导加载程序：如GRUB2，负责加载内核
- Linux内核：操作系统的核心部分
- 初始化系统：如systemd或SysVinit，负责启动服务


了解了引导涉及的基本元素之后，下一步我们需要掌握如何在启动时使用常见的引导选项。

接下来，我们会学习如何使用常见的引导选项。引导选项允许你在系统启动时临时改变内核行为或指定启动参数，这在排查故障或进行特殊配置时非常有用。例如，你可以通过引导选项进入单用户模式，或者禁用某些驱动程序以避免冲突。以下是常见引导选项的使用场景和示例：

- single：进入单用户模式，用于系统维护
- init=/bin/bash：直接启动shell，绕过正常的初始化流程
- nomodeset：禁用图形驱动模式设置，解决显卡兼容性问题

你可以在引导菜单中编辑内核参数行，将这些选项追加到参数末尾，然后按下启动键即可生效。

在掌握引导选项之后，有必要了解当前主流固件标准之间的差异，即BIOS和UEFI系统的不同之处。

然后，我们会解释BIOS和UEFI系统之间的区别。BIOS是传统的固件接口，已经使用了几十年，而UEFI是现代替代方案，支持更大的磁盘、更快的启动以及更安全的启动机制。两者在启动流程、分区表类型和安全特性上都有显著差异。以下是BIOS与UEFI的主要对比表现：

```text
BIOS：
  - 使用MBR分区表
  - 支持最大2TB磁盘
  - 文本界面，功能较为基础

UEFI：
  - 使用GPT分区表
  - 支持超大容量磁盘
  - 图形界面，支持安全启动（Secure Boot）
```

从技术原理上看，UEFI更像是一个微型操作系统，而BIOS只是简单的硬件初始化程序。

理解固件差异后，我们需要知道如何在Linux系统中直接管理UEFI设置。

之后，我们可以讨论从Linux管理UEFI的方法。现代Linux发行版提供了一些工具，允许你在不重启进入固件设置界面的情况下，查看和修改UEFI变量。例如，你可以使用efibootmgr命令来查看当前的启动项顺序，或者添加、删除UEFI启动条目。以下是管理UEFI的常用命令示例：

```bash
efibootmgr           # 查看当前UEFI启动项
efibootmgr -o 0001,0002  # 设置启动顺序
efibootmgr -b 0003 -B    # 删除指定启动项
```

这些操作通常需要root权限，因为涉及底层固件变量的修改，不当更改可能导致系统无法引导。

讲完UEFI管理之后，我们将深入探讨GRUB2引导加载器的配置，以及如何安装新的GRUB引导加载器。

接下来，我们会探讨GRUB2引导加载器的配置，以及如何安装一个新的GRUB引导加载器。GRUB2是大多数Linux发行版使用的默认引导程序，它的配置文件通常位于/boot/grub2/grub.cfg，但建议通过/etc/default/grub文件进行修改，然后重新生成配置。以下是GRUB2配置的典型步骤：

1. 编辑/etc/default/grub文件，修改超时时间、默认内核等参数
2. 运行 grub2-mkconfig -o /boot/grub2/grub.cfg 重新生成配置文件
3. 如需安装到新磁盘，使用 grub2-install /dev/sdX 命令

安装新引导加载器时，务必确认目标设备正确，避免意外覆盖重要数据。

掌握GRUB2配置之后，我们会学习如何引导到非默认目标，并设置系统的默认运行目标。

之后，我会演示如何引导到非默认目标，并且教你如何设置默认目标。在systemd管理的系统中，目标（target）取代了传统的运行级别概念，常见的目标包括图形界面目标和多用户命令行目标。你可以在启动时临时指定目标，也可以永久修改默认启动目标。以下是相关操作命令：

```bash
systemctl isolate multi-user.target   # 临时切换到多用户命令行目标
systemctl set-default graphical.target # 将图形界面设为默认目标
systemctl get-default                 # 查看当前默认目标
```

如果系统无法进入图形界面，你可以通过引导选项指定multi-user.target，先进入命令行模式再进行排查。

当你掌握了正常启动和目标切换之后，就需要学习当引导出故障时该如何处理。

在本课的最后一部分，你将学习如何排查引导流程问题，并配置MFS。引导故障可能由多种原因引起，例如引导加载器损坏、initramfs缺失、文件系统错误或驱动程序不兼容。排查思路通常是从固件设置开始，逐层向下检查内核日志和系统服务状态。以下是排查引导问题的常用步骤：

- 检查BIOS/UEFI启动顺序是否正确
- 查看内核启动日志，寻找错误或警告信息
- 使用救援模式或Live CD挂载系统分区进行修复
- 检查并重建initramfs镜像

MFS在这里指代与引导相关的某些文件系统或服务配置，具体含义需结合实际环境理解。

除了现代的systemd引导流程，我们还会简要介绍传统的System V引导流程。

![](img/2a2499007ef3d281a8f0f0a4f7ca7905_2.png)

你还会了解System V引导流程，在本课结束时你会找到实验以及实验的解答。System V是早期Unix和Linux系统使用的初始化系统，基于运行级别（runlevel）来管理系统状态。虽然现在大多数发行版已经转向systemd，但理解SysVinit仍然有助于处理老旧系统或特定场景。实验环节将帮助你把所学知识付诸实践，巩固对引导流程的理解。


本节课中，我们一起学习了Linux引导流程的完整知识体系，包括引导涉及的所有元素、常见引导选项的使用方法、BIOS与UEFI系统的区别、从Linux管理UEFI的技巧、GRUB2引导加载器的配置与安装、非默认目标引导及默认目标设置、引导故障排查与MFS配置，以及System V引导流程的基础知识。希望这些内容能帮助你在实际工作中更自信地处理Linux启动相关问题。
