

# Ethical Hacking & Penetration Testing with Kali Linux：29：主动侦察实验室 - Ping 与 Traceroute 🌐

在本节课中，我们将要学习如何从被动侦察转入主动侦察，重点掌握 ping 和 traceroute 这两个基础网络工具，并明确在授权实验室环境中安全地进行主动探测的方法。

## 主动侦察的法律边界与前提

![](img/49ddc91614853fab69257a8b4d0447ab_1.png)

主动侦察与被动侦察最大的不同在于，主动侦察会直接向目标发送网络流量，目标系统通常能够在日志中留下记录。因此，我们必须始终牢记本模块第一节课强调的核心原则：本课程演示的所有主动侦察技术，只能并且只能针对我们自己搭建的实验室虚拟机，绝对不能将任何技术用于未经授权的外部目标。

![](img/49ddc91614853fab69257a8b4d0447ab_3.png)

以下是本节课必须遵守的安全前提：

![](img/49ddc91614853fab69257a8b4d0447ab_4.png)

![](img/49ddc91614853fab69257a8b4d0447ab_6.png)

- 只在本地搭建的 Kali Linux 和 Metasploitable 实验室环境中操作
- 确保目标虚拟机属于你自己，且已获得明确授权
- 禁止扫描或探测任何公网 IP 地址或他人所有的设备

![](img/49ddc91614853fab69257a8b4d0447ab_8.png)

![](img/49ddc91614853fab69257a8b4d0447ab_10.png)

环境就绪之后，我们就可以开始使用 ping 命令来验证目标机器是否在线。

![](img/49ddc91614853fab69257a8b4d0447ab_11.png)

![](img/49ddc91614853fab69257a8b4d0447ab_12.png)

## 准备实验室环境

![](img/49ddc91614853fab69257a8b4d0447ab_14.png)

在开始任何主动探测之前，第一步是确认你的攻击机和目标机都已经正常启动并运行。如果虚拟机处于关机状态，后续的网络命令将无法获得任何响应，也就无法进行后续的侦察工作。

![](img/49ddc91614853fab69257a8b4d0447ab_16.png)

![](img/49ddc91614853fab69257a8b4d0447ab_17.png)

![](img/49ddc91614853fab69257a8b4d0447ab_18.png)

你可以按照以下步骤检查环境状态：

![](img/49ddc91614853fab69257a8b4d0447ab_20.png)

- 启动 Kali Linux 虚拟机，打开终端窗口
- 启动 Metasploitable 目标虚拟机，确保它处于运行状态
- 确认两台虚拟机处于同一个虚拟网络或宿主机网络中

## 使用 Ping 确认目标存活

![](img/49ddc91614853fab69257a8b4d0447ab_22.png)

![](img/49ddc91614853fab69257a8b4d0447ab_23.png)

![](img/49ddc91614853fab69257a8b4d0447ab_24.png)

在花费更多时间进行深入调查之前，我们需要先确认目标机器是否真的处于开机状态，并且可以通过网络到达。ping 命令是最简单的方法，它通过向目标发送 ICMP 回声请求包，并等待目标返回回声应答包来完成验证。

![](img/49ddc91614853fab69257a8b4d0447ab_25.png)

在 Kali 终端中执行以下命令，将 IP 地址替换为你的 Metasploitable 机器的实际地址，本课程示例中使用的是 192.168.56.101：

![](img/49ddc91614853fab69257a8b4d0447ab_27.png)

![](img/49ddc91614853fab69257a8b4d0447ab_28.png)

ping 192.168.56.101

如果命令正常工作，你会看到类似下面的输出信息：

![](img/49ddc91614853fab69257a8b4d0447ab_30.png)

![](img/49ddc91614853fab69257a8b4d0447ab_31.png)

![](img/49ddc91614853fab69257a8b4d0447ab_32.png)

64 bytes from 192.168.56.101: icmp_seq=1 ttl=64 time=0.543 ms
64 bytes from 192.168.56.101: icmp_seq=2 ttl=64 time=0.612 ms

![](img/49ddc91614853fab69257a8b4d0447ab_34.png)

收到回复表示目标机器已经启动并运行，并且在我们的实验室网络中可以被访问。当确认完成之后，按下 Ctrl + C 组合键来停止持续运行的 ping 进程。

![](img/49ddc91614853fab69257a8b4d0447ab_36.png)

## 使用 Traceroute 追踪网络路径

![](img/49ddc91614853fab69257a8b4d0447ab_37.png)

![](img/49ddc91614853fab69257a8b4d0447ab_38.png)

确认目标存活之后，我们可以尝试获取更多关于网络路径的信息。traceroute 命令的作用是显示数据包从我们的机器到达目标机器之间经过的每一个网络跳点，也就是每一个路由器或网关节点。

![](img/49ddc91614853fab69257a8b4d0447ab_40.png)

在终端中输入以下命令来追踪路径：

![](img/49ddc91614853fab69257a8b4d0447ab_42.png)

traceroute 192.168.56.101

![](img/49ddc91614853fab69257a8b4d0447ab_43.png)

![](img/49ddc91614853fab69257a8b4d0447ab_44.png)

如果系统提示 command not found，说明当前的 Kali 镜像中默认没有安装 traceroute 工具。解决方法也非常简单，使用 apt 包管理器进行安装即可：

sudo apt install traceroute

![](img/49ddc91614853fab69257a8b4d0447ab_46.png)

![](img/49ddc91614853fab69257a8b4d0447ab_47.png)

![](img/49ddc91614853fab69257a8b4d0447ab_48.png)

安装完成后重新运行 traceroute 命令，你就可以查看完整的路由追踪结果了。

## 实验室环境与真实网络的对比

![](img/49ddc91614853fab69257a8b4d0447ab_50.png)

![](img/49ddc91614853fab69257a8b4d0447ab_51.png)

![](img/49ddc91614853fab69257a8b4d0447ab_52.png)

在我们的实验室拓扑中，Kali Linux 和 Metasploitable 通常运行在同一台宿主机的同一子网内，两者之间没有中间路由器。因此 traceroute 只会显示一个跳点，并且响应速度非常快，因为数据包不需要经过任何实际的路由设备。

为了让你理解 traceroute 在真实世界中的能力，我们可以对比一下公网场景。如果针对一台真实的公网网站运行 traceroute，通常会显示 5 到 15 个甚至更多独立的跳点，每一个跳点都代表数据包在物理链路上经过的真实路由器，最终到达目标所属的网络。

![](img/49ddc91614853fab69257a8b4d0447ab_54.png)

这种路径信息可以帮助渗透测试人员或网络工程师大致了解目标网络的物理结构，有时还能揭示中间基础设施上属于其他组织的 IP 地址。不过在本课程中，我们始终将所有主动探测练习严格限制在自己的授权实验室环境内，不会针对任何真实公网目标进行操作。

![](img/49ddc91614853fab69257a8b4d0447ab_55.png)
