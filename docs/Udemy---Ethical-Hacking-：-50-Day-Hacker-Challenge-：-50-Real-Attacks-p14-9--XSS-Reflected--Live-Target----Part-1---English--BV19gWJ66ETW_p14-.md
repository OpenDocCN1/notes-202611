什么是跨站脚本攻击

跨站脚本攻击是 OWASP 定义的一种非常著名的 Web 攻击方式。攻击者可以在页面中插入任意类型的恶意脚本。一旦脚本被执行，攻击就可以从当前浏览器脚本传播到不同的最终用户，特别是当恶意代码被存储在服务器上时，影响范围会进一步扩大。

从定义上看，XSS 可以用下面的公式来理解：

![](img/3011912603f240e47d579750b3d3e468_2.png)

XSS = 用户可控输入 + 恶意 JavaScript + 浏览器执行


![](img/3011912603f240e47d579750b3d3e468_4.png)

XSS 的三大类型

![](img/3011912603f240e47d579750b3d3e468_6.png)

根据恶意脚本在应用中的处理方式，XSS 主要分为以下三类：

![](img/3011912603f240e47d579750b3d3e468_8.png)

![](img/3011912603f240e47d579750b3d3e468_10.png)

- 反射型 XSS：恶意脚本通过请求发送到服务器，服务器直接将其反射回响应页面中执行。
- 存储型 XSS：恶意脚本被保存在服务器中，例如评论区、论坛帖子或用户资料，其他用户访问页面时会自动触发。
- 基于 DOM 的 XSS：恶意脚本完全在客户端的文档对象模型中执行，不需要经过服务器处理。


反射型 XSS 的工作原理

在反射型 XSS 攻击中，核心步骤是寻找应用中的注入点。注入点通常是一些可被用户控制的参数，例如搜索框、用户名输入框或 URL 查询字符串。

![](img/3011912603f240e47d579750b3d3e468_12.png)

![](img/3011912603f240e47d579750b3d3e468_14.png)

![](img/3011912603f240e47d579750b3d3e468_16.png)

![](img/3011912603f240e47d579750b3d3e468_18.png)

攻击者在注入点中提交一段 JavaScript 代码，常见示例如下：

<script>alert(0)</script>

如果目标应用存在漏洞，并且没有机制来区分用户生成的内容和服务器代码，那么服务器就会把这段脚本原样返回给浏览器。浏览器收到响应后会直接渲染页面，并执行弹窗，显示 alert(0) 或 alert(1)。这就是反射型 XSS 的完整执行流程。


![](img/3011912603f240e47d579750b3d3e468_20.png)

![](img/3011912603f240e47d579750b3d3e468_22.png)

如果应用没有任何过滤机制，我们提交的脚本会被直接反射。此时页面会直接执行脚本，并渲染出带有 alert(0) 的结果，说明请求已经成功发送到远程客户端，服务器也响应了我们的查询。


![](img/3011912603f240e47d579750b3d3e468_32.png)

绕过编码与闭合标签

在某些关卡中，同样的脚本可能会被编码处理，而不会直接执行 `<script>` 标签。这时候我们可以尝试其他绕过方法。

![](img/3011912603f240e47d579750b3d3e468_34.png)

一种常见的绕过方式是尝试终止当前函数，也就是闭合标签。如果应用允许我们通过双重编码和闭合标签来构造输入，那么就有机会执行我们提供的脚本。比如，我们可以先闭合原有的标签，再插入新的脚本标签。


使用事件处理器注入

![](img/3011912603f240e47d579750b3d3e468_36.png)

除了脚本标签，攻击者还可以利用 HTML 的事件处理器来触发 XSS。常见的事件触发点包括以下这些：

![](img/3011912603f240e47d579750b3d3e468_38.png)

- onclick：用户点击元素时触发
- onmouseover：鼠标移动到元素上方时触发
- onload：页面或资源加载完成时触发

![](img/3011912603f240e47d579750b3d3e468_40.png)

在更高级的关卡中，直接插入 `<script>` 标签可能会被拦截，无法执行函数。此时我们可以改用事件处理器。例如，将 onmouseover 设置为 alert(1)，然后移动鼠标观察是否成功反射到查询中。如果 onmouseover 不行，也可以尝试 onclick。这就是利用事件处理器完成跨站脚本注入的方法。


![](img/3011912603f240e47d579750b3d3e468_42.png)

存储型 XSS 的危害等级

![](img/3011912603f240e47d579750b3d3e468_44.png)

![](img/3011912603f240e47d579750b3d3e468_46.png)

如果应用允许攻击者注入脚本，这种攻击就被称为跨站脚本攻击。反射型 XSS 是主要类型之一。如果应用支持多个字段，例如名、姓等，并且这些字段值会被存储在服务器中，那么攻击影响会进一步扩大。

想象一下，如果恶意脚本被保存在服务器的公共位置，比如评论区或论坛帖子，其他用户访问该页面时就会看到已经存储的注入脚本。在这种情况下，攻击影响会显著增加。

从危害等级来看，反射型 XSS 和基于 DOM 的 XSS 通常属于中危，而存储型 XSS 可能会升级为高危。攻击者还可以利用 XSS 窃取受害者的 Cookie，在受害者浏览器上执行远程命令，甚至远程控制受害者设备并传播恶意软件。


![](img/3011912603f240e47d579750b3d3e468_48.png)

自动化工具检测

![](img/3011912603f240e47d579750b3d3e468_49.png)

除了手动构造载荷，我们也可以使用工具来自动发现 XSS 漏洞。常见的方法包括以下几种：

- 手动测试：在注入点插入常见的 XSS 载荷，观察页面响应。
- XSS Strike：一款专门用于发现 XSS 弱点的知名工具，可以自动化扫描目标。
- Nuclei：一款开源漏洞扫描器，不仅限于 XSS，还能发现适用于应用的其他常见漏洞。

使用 XSS Strike 时，工具会发送一组查询并显示确定性评分，例如 10 表示高度可疑。在运行工具之前，请始终确保使用了最新的模板版本。当前模板库包含近 7600 个扫描项。工具运行过程中，可能会发现登录页面，并尝试注入一些值，其中部分属于 SQL 注入尝试。扫描结束后，你可以查看检测到的其他组件和漏洞。
