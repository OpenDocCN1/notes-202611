
Ethical Hacking：17：OAuth 错误配置与账户接管 [实战目标] 🔓

![](img/c6e60ec65d4718056a9f7dce7f6718f2_0.png)

在本节课中，我们将学习如何利用 OAuth 配置错误实现账户接管。OAuth 是一种常见的第三方登录协议，当网站对其配置不当的时候，攻击者可以绕过正常的身份验证流程，接管他人账户。本节课采用实战目标环境，演示从注册攻击者账户、诱导受害者登录、修改关联邮箱，到最终完成账户接管的完整过程。内容将用大白话讲解，适合完全没有安全基础的初学者阅读。

![](img/c6e60ec65d4718056a9f7dce7f6718f2_2.png)

### 什么是 OAuth 错误配置

OAuth 允许用户使用 Google、Gmail 等第三方账号登录其他网站，而不需要直接告诉网站自己的密码。如果网站在处理第三方登录回调时缺少严格验证，攻击者就可以利用这个漏洞，把受害者的账户绑定到攻击者控制的邮箱上。

![](img/c6e60ec65d4718056a9f7dce7f6718f2_4.png)

![](img/c6e60ec65d4718056a9f7dce7f6718f2_5.png)

核心概念可以用下面的公式来描述：

```text
OAuth 配置错误 = 信任第三方身份提供商 + 缺少账户绑定验证 + 允许任意修改关联邮箱 → 攻击者接管受害者账户
```

![](img/c6e60ec65d4718056a9f7dce7f6718f2_7.png)

![](img/c6e60ec65d4718056a9f7dce7f6718f2_9.png)

简单来说，正常的 OAuth 登录流程是：用户点击“使用 Gmail 登录” → 跳转到 Gmail 授权页面 → 授权成功后返回目标网站 → 目标网站创建或关联账户。如果目标网站没有检查返回的邮箱是否已经被其他账户占用，攻击者就可以先用自己的 Gmail 注册一个账户，再诱导受害者用同样的 Gmail 登录，从而覆盖或接管受害者的账户。

### 攻击步骤详解

上一节我们介绍了 OAuth 错误配置的基本原理，本节中我们来看看如何在实战目标中利用它完成账户接管。

![](img/c6e60ec65d4718056a9f7dce7f6718f2_22.png)

![](img/c6e60ec65d4718056a9f7dce7f6718f2_23.png)

以下是完整的攻击步骤：

![](img/c6e60ec65d4718056a9f7dce7f6718f2_25.png)

1. **注册攻击者账户**
   攻击者首先在目标网站上注册一个新账户，使用攻击者控制的 Gmail 邮箱。注册完成后，攻击者拥有一个合法的账户，可以在后续步骤中用来接管受害者的数据。

![](img/c6e60ec65d4718056a9f7dce7f6718f2_27.png)

![](img/c6e60ec65d4718056a9f7dce7f6718f2_29.png)

2. **发起通过 Gmail 的 OAuth 登录**
   攻击者在浏览器中打开目标网站的登录页面，选择“使用 Gmail 继续”或类似的第三方登录选项。此时浏览器会跳转到 Gmail 的授权页面，攻击者需要选择一个 Gmail 账户进行授权。

![](img/c6e60ec65d4718056a9f7dce7f6718f2_31.png)

3. **使用受害者身份继续登录**
   在实战环境中，攻击者可以切换浏览器会话，或者诱导受害者在同一台设备上使用自己的 Gmail 账户登录目标网站。如果网站没有验证该 Gmail 邮箱是否已经与其他账户绑定，受害者的登录请求可能会被错误地关联到攻击者之前注册的账户上。

![](img/c6e60ec65d4718056a9f7dce7f6718f2_33.png)

4. **修改或删除受害者的关联邮箱**
   一旦账户被错误关联，攻击者就可以进入账户设置页面，修改绑定的邮箱地址，或者删除原有的受害者邮箱。这一步是关键，因为它让攻击者彻底控制账户的恢复和登录权限。

![](img/c6e60ec65d4718056a9f7dce7f6718f2_35.png)

5. **完成账户接管**
   修改关联邮箱后，攻击者可以使用受害者的个人信息登录该账户，执行任意操作，例如查看隐私数据、修改密码、删除内容等。此时，受害者已经失去了对自己账户的控制权。

![](img/c6e60ec65d4718056a9f7dce7f6718f2_37.png)

### 防御建议

为了防止 OAuth 错误配置导致账户接管，开发者和运维人员应当注意以下几点：

- 在处理第三方登录回调时，务必验证返回的邮箱地址是否已经存在于系统中，如果已存在且关联的账户不是当前登录用户，应拒绝关联并提示错误。
- 为账户设置增加二次验证，即使攻击者获取了关联邮箱，也无法轻易登录。
- 定期审查 OAuth 集成代码，确保所有第三方身份提供商都经过严格配置和测试。
- 对账户设置中的邮箱修改操作增加密码确认或手机验证码，防止未授权的更改。
